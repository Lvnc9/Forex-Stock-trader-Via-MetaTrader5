# Playbook 03 — Take-profit (Bug C)

## Goal
Improve TP hit rate via staged targets: TP1 = 0.5×H, TP2 = k×H (default k=0.51 pending FX calibration). Optional trail after TP1.

## What to load
1. `hs-curriculum/L0-diagnosis.md` (Bug C)
2. `hs-curriculum/L1-distill.md` chunk 8
3. `hs-curriculum/hs-spec.v1.json` → `stops_targets`
4. Labels with `H`, `tp1_price`, `tp2_price`, `tp1_hit`, `tp2_hit` when available

## What to touch (when MQL / EA code is pointed)
- Measure H: `|head_extreme − neckline_at_head_time|`
- TP order placement / modify (partials at TP1, remainder at TP2)
- SL: beyond RS ± `sl_atr_buffer` × ATR
- Optional trail after TP1 (`trail_atr`)
- Backtest metrics: TP1/TP2 hit rates separately

## What NOT to change
- Detection / score (playbook 01)
- Confirmation / entry mode logic (playbook 02)
- Do not “fix” hit rate by widening SL past spec without a new TUNABLE + label study
- Do not make sole default TP = 1.0×H

## Done-when checklist
- [ ] T1: staging defaults match spec (0.5 / k=0.51)
- [ ] T3: full 1.0×H is not the sole default target
- [ ] T2: TP1/TP2 hit rates reported; TP1 meets floor TUNABLE
- [ ] T4: SL = RS ± ATR buffer; documented vs TP1 R-multiple
- [ ] T5: trail (if enabled) never moves SL against the trade
- [ ] `k` and TP1 mult remain tagged TUNABLE for FX re-estimation
